# Private proposal reviewer AI

This is a future, default-off source candidate. Local fake-provider tests do not
establish live model access, provider billing, a running cleanup schedule or
hosted acceptance. Keep the current shared proposal edition unchanged while it
is being presented. Source activation requires the normal release gates and a
coordinated new immutable campus review edition.

## Scope and interface

Only an unlocked, current private proposal edition in its separately configured
owner runtime can expose Chats. The normal public sample, signed-in campus
workspace, native Conversation and older Trial remain separate. A fictional
perspective or review display name supplies no employee identity or grant.
Assistants and Voice remain Coming soon. Sending, payments, microphone capture
and work-changing tools remain unavailable.

Before a paid question, show the exact selected fictional project/ticket fields,
question and maximum reservation. The closed snapshot includes bounded titles,
versions, statuses, assignments, buildings and due dates. It excludes notes,
files, photos, review comments, contact details, mailboxes and financial records.
These are reviewer-supplied browser records, not verified campus facts. Responses
are plain text with references only to those supplied sources; inspect current
work before acting. A perspective, scope, source or navigation change withholds
old answers. No question or answer is persisted in browser storage; only opaque
request receipt fields are retained for recovery.

All four actions use the original same-origin session and CSRF token. Admission
rechecks host, mount, password grant, immutable version/source/build, browser and
the exact approved connection. Error responses expose no provider diagnostics,
secret, SQL, private URL or question. The browser never contacts OpenAI directly.

## One lifetime spending authority

One pre-existing owner-local synthetic anchor and exact ledger govern the entire
related $5 lifetime campaign. No membership is added to the anchor. A missing,
replaced, duplicated or mismatched ledger refuses work; availability and first
requests never initialize it. Related prior spending and unresolved exposure
remain part of the same total. Keep every other paid Enterprise path off.

Receipt claim, full bounded reservation, charge attachment and single dispatch
claim commit before provider IO. Replay is a read of the original request, not
a new call. A timeout, invalid usage, lost authority or uncertain response retains
exposure and pauses the campaign. Never reset a ledger, refund an uncertain
charge, copy it to another silo or automatically retry a provider request.

A saved prepared preview requires explicit atomic cancellation before it can be
forgotten. If a claim wins the race, cancellation fails and the receipt remains.
Expired accepted/rejected/cancelled outcomes require explicit acknowledgment;
their content is not redisplayed. Claimed, reserved, dispatching and uncertain
outcomes cannot be acknowledged as settled or released by the browser. Async
callbacks must still own their exact receipt before changing state or storage.

## Retention and deactivation

Sharing previews last two minutes; encrypted server question/snapshot/result
content is withheld after ten minutes. Cost records, digests and content-free
tombstones remain. This does not claim erasure of user copies, backups or provider
records. The transport requests `store: false`; see the official
[Responses conversation-state documentation](https://developers.openai.com/api/docs/guides/conversation-state).

The explicitly registered `proposals:prune-reviewer-ai` command takes an absolute
nonsecret pins JSON file, its reviewed SHA256 and a limit from 1 to 100. Pins are
exactly: client_id, silo_id, mount, tenant_id, area_id, ledger_id,
inventory_evidence_hash, prior_spend_evidence_hash and prior_spend_microusd.
Store that file privately in the approved owner runtime; include no API key.
The command independently checks the actual silo markers, anchor, membership
absence, sole ledger and immutable baseline. It cannot admit calls or create,
reset or refund spend.

Before activation, install and observe a recurring owner-runtime-only cleanup
operation at least once per minute, with non-overlap and bounded batches. Its
reviewed command has this shape; resolve and verify each destination first:

```sh
ENTERPRISE_RUNTIME_ROOT="$OWNER_RUNTIME" "$REVIEWED_PHP84" \
  "$APP_RELEASE/apps/enterprise/artisan" proposals:prune-reviewer-ai \
  --pins="$APP_PINS_JSON" --sha256="$APP_PINS_SHA" --limit=100
```

Record a successful run, expiry erasure and backlog handling. A source command
alone is not evidence of an installed schedule. Do not use the retail scheduler
or another runtime's configuration as a substitute.

To deactivate, set both reviewer UI and paid gates false through the reviewed
isolated configuration procedure. Run the same pinned cleanup with
`--deactivated` in bounded batches until zero; that mode erases even unexpired
content only when both gates are explicitly false. Preserve charges, holds,
audit and tombstones. Reconcile paused or uncertain requests separately.
