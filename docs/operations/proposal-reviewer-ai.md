# Private proposal reviewer AI

This is a future, default-off source candidate. Local fake-provider tests do not
establish live model access, provider billing, a running cleanup schedule or
hosted acceptance. Keep the current shared proposal edition unchanged while it
is being presented. Source activation requires the normal release gates and a
coordinated new immutable campus review edition.

## Scope and interface

Only an unlocked, current private proposal edition in its separately configured
owner runtime can expose Chats. The normal public sample, signed-in campus
workspace, native Conversation and older Trial remain separate. A fictional
perspective or review display name supplies no employee identity or grant.
Assistants remain Coming soon. Explicit microphone input and spoken playback use
the same text client; sending, payments and work-changing tools remain unavailable.
Any supported computer or phone can unlock the approved edition and start its own
requests. Session/CSRF/receipt ownership is not a physical-device allowlist.
Cross-device continuation of short AI history is a separate product choice.

Before a paid question, show the exact selected fictional project/ticket fields,
question and maximum reservation. The closed snapshot includes bounded titles,
versions, statuses, assignments, buildings and due dates. It excludes notes,
files, photos, review comments, contact details, mailboxes and native financial
records. Schema2 can include explicitly fictional project-level estimate/recorded
cost inputs, exact integer currency/basis comparisons, current saved buildings,
assignments and canonical contractor plans under its current source/persona gates.
These plans never establish physical attendance or building cost allocation.
These are explicitly fictional demonstration records, not verified campus facts. Responses
are plain text with references only to those supplied sources; inspect current
work before acting. A perspective, scope, source or navigation change withholds
old answers. No question or answer is persisted in browser storage; only opaque
request receipt fields are retained for recovery.

The source candidate supports two separately admitted evidence modes. An edition
without a shared-workspace descriptor retains its fictional browser snapshot.
An immutable `review_workspace` descriptor selects the encrypted server-held
fictional workspace and its current scoped projection; malformed or unavailable
shared admission never falls back to browser data. The browser sends only the
expected workspace revision and selection for sharing preview. The server reads
the facts again, rejects supplied browser snapshots and binds the exact server
selection/revision pin into consent before and after provider IO. Stale status
reads withhold old content while preserving the original receipt and cost; grant
revocation still denies access. Neither mode retrieves actual college records.
The shared store, transport and mounted HTTP/browser source checks are integrated;
hosted activation, retention scheduling and immutable-edition transition remain
separate gates. See [shared workspace](proposal-reviewer-workspace.md).
Native signed-in Conversation already
retrieves currently authorized server records; never invent a native User or grant
a reviewer those records to bridge this distinction.

All four actions use the original same-origin session and CSRF token. Admission
rechecks host, mount, password grant, immutable version/source/build, browser and
the exact approved connection. Error responses expose no provider diagnostics,
secret, SQL, private URL or question. The browser never contacts OpenAI directly.

## One lifetime spending authority

One pre-existing owner-local synthetic anchor and exact ledger govern the entire
related $5 lifetime campaign. No membership is added to the anchor. A missing,
replaced, duplicated or mismatched ledger refuses work; availability and first
requests never initialize it. Related prior spending and unresolved exposure
remain part of the same total. Keep every other paid Enterprise path off.

Receipt claim, full bounded reservation, charge attachment and single dispatch
claim commit before provider IO. Replay is a read of the original request, not
a new call. A timeout, invalid usage, lost authority or uncertain response retains
exposure and pauses the campaign. Never reset a ledger, refund an uncertain
charge, copy it to another silo or automatically retry a provider request.

A saved prepared preview requires explicit atomic cancellation before it can be
forgotten. If a claim wins the race, cancellation fails and the receipt remains.
Expired accepted/rejected/cancelled outcomes require explicit acknowledgment;
their content is not redisplayed. Claimed, reserved, dispatching and uncertain
outcomes cannot be acknowledged as settled or released by the browser. Async
callbacks must still own their exact receipt before changing state or storage.

## Retention and deactivation

Each follow-up may explicitly include at most two accepted server-owned prior
receipts from the same session, edition, settings and exact fictional snapshot.
The sharing preview displays their exact question, answer and source refs. Prior
answers resolve wording only and never count as evidence. History uses manual
input with `store: false`, no provider Conversation/previous-response identifier
or persistent memory. New follow-up content inherits the earliest original
ten-minute expiry; activity never renews it. A final pure receipt/content read
after all admission work rejects history that expires before provider HTTP.
A post-claim refusal retains the original cost hold and reconciliation semantics.

Sharing previews last two minutes; encrypted server question/snapshot/result
content is withheld after ten minutes. Cost records, digests and content-free
tombstones remain. This does not claim erasure of user copies, backups or provider
records. The transport requests `store: false`; see the official
[Responses conversation-state documentation](https://developers.openai.com/api/docs/guides/conversation-state).

The explicitly registered `proposals:prune-reviewer-ai` command takes an absolute
nonsecret pins JSON file, its reviewed SHA256 and a limit from 1 to 100. Pins are
exactly: client_id, silo_id, mount, tenant_id, area_id, ledger_id,
inventory_evidence_hash, prior_spend_evidence_hash and prior_spend_microusd.
Store that file privately in the approved owner runtime; include no API key.
The command independently checks the actual silo markers, anchor, membership
absence, sole ledger and immutable baseline. It cannot admit calls or create,
reset or refund spend.

Before activation, install and observe a recurring owner-runtime-only cleanup
operation at least once per minute, with non-overlap and bounded batches. Its
reviewed command has this shape; resolve and verify each destination first:

```sh
ENTERPRISE_RUNTIME_ROOT="$OWNER_RUNTIME" "$REVIEWED_PHP84" \
  "$APP_RELEASE/apps/enterprise/artisan" proposals:prune-reviewer-ai \
  --pins="$APP_PINS_JSON" --sha256="$APP_PINS_SHA" --limit=100
```

Record a successful run, expiry erasure and backlog handling. A source command
alone is not evidence of an installed schedule. Do not use the retail scheduler
or another runtime's configuration as a substitute.

To deactivate, set both reviewer UI and paid gates false through the reviewed
isolated configuration procedure. Run the same pinned cleanup with
`--deactivated` in bounded batches until zero; that mode erases even unexpired
content only when both gates are explicitly false. Preserve charges, holds,
audit and tombstones. Reconcile paused or uncertain requests separately.

## Speech acceptance boundary

Start voice explicitly requests browser microphone/speech permission. Recognition
fills the same question and prepares the same exact sharing preview. Each spoken
turn still needs its own Send once action. Microphone capture stays off during
playback; Interrupt retires playback before listening again. Stop before sharing
retires late previews; Stop after dispatch only retires audio and preserves the
request receipt/cost. Scope changes, navigation and hidden tabs stop local audio.
Unsupported recognition, denied consent and uncertain outcomes retain typed input
and saved status. Browser recognition may use the browser vendor's service; no
server transcription provider or additional paid permission is silently enabled.

Local evidence includes actual private UI/CSP rendering and compiled entry in
Chromium/WebKit across independent desktop/phone-sized contexts, intercepted
endpoints and synthetic speech. This is not genuine recipient unlock, native
workspace retrieval, provider billing, physical microphone or physical mobile
acceptance. Complete those applicable checks against an approved hosted candidate
before making live claims. Current immutable review access/comments must survive
an explicitly reviewed publication transition; do not silently rebind its source.

## Provider-free private review simulation

A current password-authorized, browser-local proposal review may expose the
Demo assistant while paid reviewer AI is disabled. Paid and simulated controls
are mutually exclusive. Trusted presentation selects it;
URL, saved browser state and perspective names do not. Public presentation and
an immutable shared-workspace descriptor do not select this path. Shared mode
retains its existing fail-closed admission with no browser fallback. Archived v5
and all existing passwords, comments and editions remain unchanged.

Choose a permitted fictional department, ask for a job, then follow up about that
same current record. Saved High/Low priority is reported as recorded; missing or
invalid priority stays unknown. Text and exact candidate selection work without
the voice SDK. Talk requires an explicit click; Stop and Interrupt reuse the
existing voice lifecycle. Leaving Ask or hiding the page stops local voice and
retires late callbacks while retaining page-local drafts/outbox. Changing
perspective stops voice and clears the previous perspective's RAM drafts,
previews and outbox. Browser speech may use its speech service. No model callback
or paid provider is wired to simulation.

The chosen job can prepare an editable demo email. Select a currently permitted
department, review the exact subject/body, then choose Simulate send. Only a
RAM-only demo outbox entry appears; no real recipient, mailbox, provider,
notification, campus write or email delivery exists. Confirming the same preview
returns one original simulated outcome. Source changes and perspective changes
retire its authority. Drafts/outbox are page-local, not shared or durable after
reload; actual proposal page comments remain a separate saved review channel.
A new immutable publication and source-bound acceptance remain separate actions.
