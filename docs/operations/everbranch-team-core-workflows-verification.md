## Implemented daily-work behavior

**Task links:** canonical web URLs carry an explicit workspace and task UUID, plus an optional comment UUID. The existing authenticated tenant resolver selects the workspace without signing out, and current Team membership/rollout/entitlement and task policy run before HTML. Wrong-workspace IDs return no record; inaccessible private tasks expose no work content. Task API/native bearer responses add the canonical URL. After normal data loading, the web page hydrates the requested task and focuses an existing authorized comment. Opening/list-filter changes and successful detail hydration keep the address consistent; the existing browser-history reauthorization remains. Copy-link has a selectable readonly fallback for unavailable clipboard permissions. Native app dispatch, OS sharing, project/portfolio/profile/approval links and supported-device restoration are not implemented by this slice.

**Reviewed follow-ups:** `task.follow_up` passes through the same tenant-locked WorkGraph/repository and existing web/native transport. Current source read access, exact source version, exact reviewed versions for every destination project and an explicit sharing review are required. A destination privacy change refuses creation until its current access label is reviewed again. An optional source comment must still exist and be undeleted. New title, new description, explicit eligible assignment/dates/priority and chosen editable project membership are independent fields; a member's default destination is a private personal task. Guests need an editable project; viewers cannot create. No source note/comment/file/history/grant/child/recurrence/dependency/custom field is automatically copied or modified. Only protected source ID/version/comment/time provenance is retained alongside the new task. Assignment can create the existing permission-aware internal Inbox event; no external notification is dispatched.

Public task/search/retry projections reveal a source link/title/current-change indicator only when that reader currently has source access. Removing source access hides provenance without deleting already intentional independent work. Missing/deleted comments do not leak comment IDs. Native private revisions retain original source records; source provenance does not grant login or object access. The new command's child creation, provenance, events and receipts commit atomically. Retrying the identical UUID request returns the one prior task; a changed payload on that key conflicts. Replays reauthorize the new task and filter source metadata against current permissions.

**Draft and conflict handling:** the dialog begins with empty new title/notes, no inherited assignment/date and a clear destination/review notice. Stale source or destination versions refuse creation atomically, refresh the currently authorized source and destination labels without silently dropping a selected target, retain typed new text and uncheck acknowledgement. An ambiguous/lost response freezes content and retains its request identity for explicit retry; closing retains the draft and blocks workspace switching until resolved. Access refusal hides original details and seals the user's newly typed title/notes as readonly, selectable text; no automatic purge is introduced. Explicit unsent-draft discard never deletes source or saved tasks. Drafts are memory-only: before-unload prompts warn about unsaved follow-ups, but browser restart/encrypted durable recovery is not promised. The corrected existing native preservation patch/write/recovery gates stay unchanged and off.
