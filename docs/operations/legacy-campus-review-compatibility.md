# Existing campus review compatibility — source candidate

The active private review binds its campus screens to immutable source and build
metadata. A later shared-workspace/AI release changes those sources. Preserving
database rows alone does not preserve the existing link: it needs an explicitly
admitted renderer for the original edition and a separate new-edition transition.
This source is not runtime admission or permission to publish/deploy.

belongs in this artifact.

The loader refuses unknown/missing/tampered members, links, unsafe file modes and
out-of-bound sizes. Views and assets are retained as verified in-memory bytes.
The isolated Blade factory cannot fall back to current templates, global view
composers or a compiled filesystem cache. Removing verified artifact files after
construction cannot replace the retained render input. It renders fictional
browser work and the existing review overlay only.

The current application still performs host/mount/owner-runtime, tenant, password,
grant, expiry and revocation checks, then repeats access after buffered rendering.
Names remain self-selected display names. Existing encrypted comments, exact

## Exact registry and feature separation

`service_proposals.campus_review.legacy_versions` is EMPTY by default. A reviewed
runtime entry maps one exact Version ID to exactly `tenant_id`, `content_hash`
and renderer `lees-mcrae-v5`. The stored Version must also match the complete
original14-page manifest, client reference, permitted audience and current
expiry/revocation state. A renderer never supplies an unlock or tenant grant.
Do not infer an actual content hash or local tenant ID from a source fixture.
The isolated owner config reads only the explicitly supplied
`SERVICE_PROPOSALS_CAMPUS_REVIEW_LEGACY_VERSIONS_JSON` map (maximum10 entries and
12,000 bytes). It requires the configured proposal-owner purpose and the same
owner-local tenant, exact UUID/hash/string/integer types and no extra row fields.
Invalid supplied configuration remains invalid and closes review admission;
it is never treated as an empty map or a grant. No value is installed by this
source change. Tests of this config assembly use fictional subprocess input and
confirm that AI/workspace flags remain off.

`resolveReviewEdition` is for display, review context, names, feedback and campus
activity. `assertCurrent` remains strict and byte-identical in its original
method body; new publication and AI/shared-workspace admission continue to use
it. Registered legacy IDs are explicitly denied additional AI/workspace authority
before session nonce creation or service dispatch, even if other flags are on.
The old renderer receives no shared-workspace, AI, trial or provider descriptor.

## Required transition evidence

Before an approved feature release, collect action-time read-only metadata for
the actual active Version, owner-local tenant, content hash, complete manifest,
expiry/revocation, payload ciphertext and existing comment bindings. Reconcile the
reviewed source SHA with the explicit runtime allowlist and operator configuration
in the same atomic release procedure. An empty registry cannot preserve the old
campus screens after a source-changing release. Source tests do not authorize
changing that registry, promoting an artifact or activating the release.

Keep the original URL, selected names and comments on their original Version.
Create a new immutable edition only under its specific publication approval;
never overwrite the old payload or reuse its comments for a new binding. The new
server workspace needs a reviewed seed/import and conflict plan that preserves
actual existing edits and canonical plans. A fresh20-job test seed is not that
recovery. Shared mode uses separate pending-edit storage and reads no old local
work state. Preserve the original browser-storage behavior, and isolate any
future public-browser migration from the old edition's storage namespace.

Hosted acceptance must verify old password access, all original screens/workflow,
reviewer selection, existing/new comments and replay, activity and PDF/proposal
links, alongside the new edition's persisted workspace and access isolation.
Recheck the existing website/Fleet and `/ready`. No provider/scanner/SMS/email or
payment activation follows from this compatibility procedure.
