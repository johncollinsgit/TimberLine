# Private owner local capture screen — source only

This screen is a local observational export, not an import, converter, publication,
shared initializer or grant. It is independently disabled by default. No actual
human storage, credentials, runtime approval map or live deployment was used.

Use the existing real owner sign-in and exact private proposal-owner runtime.
The browser GET never reads tab storage. The explicit **Download this tab’s edits**
button first asks the server for a short-lived, metadata-only owner check, then
calls the independently reviewed pure helper once. Only the fixed legacy
sessionStorage key is read; no storage key is created/deleted/upgraded/reset.
The original raw text, byte/base64 copy and SHA are retained without Unicode
normalization. Invalid scalar/oversize/unavailable/missing inputs produce no file.
Malformed/nonobject JSON may be saved as a refused original for manual review.

The owner-runtime approval must be exactly one server-configured Version entry
with the closed pins documented by ReviewerLegacyCapture. It must match the
actual tenant/client/silo/storage, active browser-only current or already-registered
legacy edition, canonical manifest hash, source/build, exact combined module hash and
absolute expiry no later than Version expiry. Any present review_workspace key
closes access, even null/malformed. Do not create a legacy registration, account,
password grant, anchor or new edition merely to enable capture. Map activation
and a real capture remain separately held for root review/explicit approval.
The initial screen packet supplied literal disabled configuration. A separately reviewed [Enterprise-only metadata seam](reviewer-legacy-capture-configuration.md) now supplies source support for a future closed ENV/config-cache procedure. It installs no actual values or flags. Test config() overrides only create synthetic local acceptance conditions; they are not real runtime setup. A separately reviewed operator/host-config procedure and exact Version approval are still required before activation or actual capture.

Source hooks are deliberately separate: config default-off, exact route include
before the common session-lock loop, exact outer boundary, narrow ResponsePolicy
marker and the five exact manifest paths. Preserve cap256 and strict assertCurrent;
review the combined closure before integration. New JS modules are not glob-loaded
by the existing renderer; this minimal page alone explicitly composes the exact
reviewed helper bytes with the new UI module under an exact CSP SHA.

Authentication is the existing real password login, not a reviewer name or a
synthetic User/Request bridge. Fresh locking User/membership/Version reads bracket
source/marker IO in a read-only transaction. All runtime/auth/session/CSRF guards
still execute. The outer boundary only sanitizes its exact capture paths and
preserves the existing GET login redirect. Normal session/login state can change;
the capture service creates/updates no content, grants, graph, journal or ledger.
POST authorize accepts only five metadata fields and returns a <=60s observation
binding; raw edits are never sent, rendered, logged or stored on the server.
CSRF stays transient and is not included in the local export.

The generic legacy key is shared across historical fictional presentations. A
runtime approval, exact module SHA or observed Version ID does **not** prove the raw edits belong
to that Version, person or device. The file explicitly says version/authorship
unknown, schema/duplicate keys unchecked, no conversion allowed, one key/one tab.
Capture all relevant old tabs/devices separately before any upgrade decision.
Missing is not evidence of no work. Nothing here reconciles conflicting tabs,
converts unsupported fields or claims lossless conversion. Already downloaded
private files cannot be remotely revoked; keep them private and review manually.
