## Two durable responsibilities

The client runtime holds fictional client work in the real Enterprise
persistence/ACL services, using its own database, restricted account, private
environment/key/storage, cookie and narrowly mounted application prefix.
Verify create/edit/assign/workflow/reload, private uploads/downloads, department
isolation, cookies and release survival after the protected release. Passing
local tests does not verify this hosted runtime.

Proposal authoring belongs to Evergrove's owner business. The client silo guard
requires exactly one tenant per database, so never add a second owner tenant to
the client database or grant a client coordinator proposal-owner privileges.
The same Enterprise application can serve a separately configured owner silo;
the reviewed source reuses its auth and immutable proposal engine.

The additional owner database, restricted account, private environment/key/storage,
narrow route and independently verified owner membership require their own
action-time approval. Keep exact operational destinations and approval records in
the private release handoff, outside PR descriptions. Do not borrow retail
tenancy, reuse client credentials or bypass the singleton silo guard. Reuse of
the existing application/server is practical; authenticated capacity and route
verification still precede any installation. No new billable infrastructure is
part of the source integration.

The runtime must explicitly bind its proposal-owner purpose, installed client
UUID, silo UUID and tenant ID. Feature/write/publication/review flags default
off. The server rechecks the exact installed claim, singleton owner tenant,
recipient host allowlist and immutable review build before handling requests.

## Bound reviewer experience

An authorized owner publishes an immutable reviewer version for client reference
`lees-mcrae-college`. The server attaches a fixed campus page list and bounded
source/build fingerprint, never a reviewer-provided file path. Access is subject
to the original password grant, expiry/revocation, host and request limits.
The page renderer never imports owner-private campus locations or memberships.

The same campus UI offers Open proposal and a Review this page dialog. Ross,
Sarah and Paul are self-selected labels, explicitly not verified identities.
Names and comments persist on the server against the immutable version, current
build and page. The display-name selection is rechecked on each comment write.
Changing a proposal/source build requires a new publication; old links fail
closed rather than silently attaching feedback to different content.

Drafts are partitioned by version ID/hash, build/source, page and display name.
The exact body and idempotency key are retained before submission. Interrupted
or uncertain requests retry the same payload; changing an unconfirmed comment
does not create a second dispatch. A stale/expired/revoked/CSRF-invalid context
locks writes and removes displayed comments until a verified refresh succeeds.
If browser storage fails, the in-tab exact retry remains available and the UI
states that reload may lose the draft. Workflow review controls live outside
React and hidden tour dialogs, so canvas renders cannot remove them.

Campus operational edits in this reviewer route are explicitly fictional and
local to the browser. Review comments are the server-persisted part of that
route. Do not call it a persistent operational workspace or use public sample
roles as authorization. The separate approved client runtime supplies that
operational acceptance path.

Chats, Assistants and Voice are compact Coming soon placeholders in this
fictional demonstration. Chat submission, microphone controls, generated
workflow drafts, Home AI summaries and AI usage navigation are unavailable.
No existing chat history is fabricated. Native signed-in record-backed Ask
retains its current authorization and independent feature gates. The Financial
cart still compares illustrative usage costs; it executes no AI or sending.
Live reviewer AI is a separate later release and acceptance milestone.
