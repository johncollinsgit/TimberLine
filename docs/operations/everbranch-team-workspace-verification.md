## Implemented behavior and limits

The shared web controller adds `GET /team/workspaces`. It resolves the caller through existing tenant middleware and `TeamWorkAccess`, then lists only that user's active memberships that currently pass the exact Team rollout, verified-active-user, recognized-role and canonical module entitlement rules. Existing dedicated soccer routing stays excluded via its established access service. Results contain only workspace ID/name/slug, a server-generated same-app Team URL and current indicator: no project/task/member contents, grants, invitations, account creation or role changes. Literal name/slug search and 25-item pages are filtered after authorization. Responses remain private/no-store. Workspaces without Team availability remain accessible through their existing app surfaces; this chooser is intentionally Team-specific.

The existing Team data response adds an explicit workspace identity, also inherited by the existing gated bearer adapter. Responsive web Team has an active-workspace label and chooser. Navigation loads a new document using the existing tenant resolver and repeats authorization on arrival; it does not merge tasks/projects or persist a new task cache. Unsaved task/planning edits, an unsent comment, selected/uploading files, another open editor and pending mutations block switching. The user must finish or deliberately clear/close work first. Older directory searches cannot overwrite newer results; late request results cannot hydrate a departing document. Restored browser-history documents reload through current access checks. A supplied directory URL must match the same origin, canonical Team path and expected workspace token before navigation.

This does not implement a native Team renderer, device cache encryption, offline account switching or pending-action recovery. Existing native bearer calls were tested separately for both workspace scopes and revocation. No mobile authentication changes, automatic purge, scheduler, external notification, production entitlement changes or new schema were introduced. Directory permission checks currently enumerate the user's own memberships and filter before result pagination; very large multi-workspace membership performance remains unmeasured.
