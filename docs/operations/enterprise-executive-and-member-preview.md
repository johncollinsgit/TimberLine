# Executive demonstration and private visibility preview

The public campus demonstration defaults a fresh tab to **Blaine J. Hansen — COO
demo admin persona**. This is a fictional presentation, not his account, an
administrator grant, college approval or purchasing authority. The sample
transport rejects every mutation in this perspective before processing receipts.
Its synthetic `demo-executive` ID is never a native user ID. Switching to a
department manager sample is required to operate fictional workflows.

The overview derives work counts and links from the configured sample records.
Its four workspace nodes reuse the existing sample area IDs. Live, Onboarding
and Planned are explicitly simulated rollout stages; none asserts a provisioned
client, connected provider or additional campus. Cards open current supporting
project, Roll Call, calendar, certificate, invoice or period-report screens.
Capacity and budget variance remain unavailable when authoritative inputs are
absent. Pending/denied scope changes clear the overview synchronously.

The proposed 1,000 / 2,000 / 2,500 software figures are separate from job costs,
invoice packets and work budgets. Currency, cadence, setup, onsite and timing
terms remain uncommitted where not supplied. Pricing & billing opens this
planning section; it cannot create a subscription, charge or entitlement.
Open proposal remains unavailable until the separate correct-client proposal
exists. The executive priorities branch has its own saved step and opens the
same screens; it is not a competing demo.

## Private existing-member data preview

`GET /enterprise/role-preview` uses the dedicated runtime's current tenant and
the `operations_enabled` gate. A fresh active verified owner/admin may select
an existing active verified member in the current authorized department. The
server intersects both people's current department and native project/task ACLs.
It returns bounded project/request summaries and explicit returned/scan coverage.
Counts are returned records, never concealed totals. Linked requests require
both actors to read the canonical task. Private objects remain protected even
when one actor is a tenant administrator.

The People screen labels this **Admin read-only data preview**. It includes the
current area's actual tenant/department membership roster, including viewers,
rather than presenting assignment editors as a complete roster. Custom group
administration is not added. Choosing a member changes the server projection;
it does not impersonate them, replace the signed-in identity, issue a token or
alter permissions. Descriptions, comments, files, contact details, finance and
mailbox contents are excluded. Record links return to the observer's own
authorized workspace. Every scope change clears old data; aborted/late responses
cannot repaint another scope. Current-role denial clears the roster and preview.

`EnterpriseRolePreviewTest` exercises the actual independent runtime with durable
native ACL records, role/member revocation, tenant/department/private denials,
read-only behavior while writes are paused, bounded results and no writes or
file/mailbox/provider access. UI tests cover stale responses and denial. Browser
helpers check keyboard, touch and desktop/phone/iPad viewports. These are source
and isolated-fixture checks, not hosted acceptance or physical iPad testing.

Real campus provisioning/access, protected review/release, provider approvals
and actual-device acceptance remain separate. Backup/restore remains plan-first.
