# Enterprise text conversation backend candidate

This is a separately reviewable backend milestone, disabled by default. It is not completion of live conversational AI or two-way voice. The deployed UI has not been changed or provider-verified by this work. Existing COO record checks remain explicitly deterministic and use no model. No local model is used.

## Implemented source behavior

Authenticated `POST /enterprise/conversation/turns` takes only current area, one of overview/building/costs, an exact saved building ID when relevant, a question and stable session/request UUIDs. Existing WorkspaceAccess, ReadOnlyAssistant and canonical native object policies supply at most eight current sources; cost access remains owner/admin-only. Source links come from the server's exact authenticated source route. They cannot be supplied or generated by the model. Cost comparisons use integer selected inputs, separate currencies, estimate/recorded-cost basis and null for missing evidence; estimates are never approved budgets. No staffing capacity is inferred.

The only provider adapter is a fixed OpenAI Responses text endpoint. It uses a dedicated approved connection, dated model snapshot, strict answer/reference schema, no tools/streaming/background work/redirects/automatic retries, `store:false`, and a bounded output token count. History is server-owned, encrypted and restricted to this user/silo/tenant/area/intent; at most six retained messages, twelve turns and ten minutes. Current native ACLs/source versions/connection approval are rechecked before dispatch, returning text and replay. Role preview supplies no authority. An actual role or source change discards old generated text even when the provider cost has already been metered.

`POST /enterprise/conversation/sessions/{id}/end` requires current access and `confirm_end:true`, scrubs conversation content and keeps content-free audit and lifetime spend evidence. Expiry denies access immediately; the existing `enterprise:voice-prune` retention command also scrubs expired conversation content. Automatic background scheduling/production changes are outside this source milestone. This short conversation is not a saved assistant or persistent preference memory.

## One lifetime $5 campaign

The managed ClientSilo filesystem/database binding, TrialStore synthetic campus anchor and separately approved existing ledger UUID/baseline must match the exact approval. Conversation never initializes a missing ledger: reservation, dispatch claim, settlement and pause recheck the exact existing ledger under the campaign lock. Missing/replaced/deleted ledgers fail closed, including uncertainty cleanup. Before provider I/O, TrialBudget reserves the *entire approved model context* at the approved inclusive worst input/cache-write ceiling, plus the enforced maximum output and per-call overhead. The prompt byte bound is only a request-size guard, not a claimed token estimate. If a safe full-context maximum cannot fit in the remaining campaign, no HTTP occurs. There is no extra token-count API request.

The existing MySQL campaign named lock and transaction serialize the one campus ledger across workers. A durable charge moves reserved → dispatching before HTTP. Immutable request/scope/config digests prevent duplicate dispatch; exact completed replay uses current ACLs. Pending, interrupted or uncertain keys cannot create a second call. Known completed responses settle to a conservative ceiling computed from verified input/output usage. This is not an invoice reconciliation claim. Unknown usage, timeouts, wrong model/tier, redirects/errors, invalid text/citations or unsupported actions hold the full maximum and pause all new campaign spending. Never refund an ambiguous completion or reset a ledger to retry. A reviewed operator reconciliation is required before resuming; this milestone deliberately supplies no unpause/refund shortcut.

The cap includes verified aggregate prior trial and acceptance spend. Its baseline/anchor are immutable once the ledger exists. This source uses one approved campus database ledger; it does not claim that independent owner/campus schema ledgers aggregate automatically. While conversation is enabled, the older controlled-trial routes and paid Ask/voice/briefing-refresh/workflow-propose/email-confirm endpoints return 404, regardless of poisoned legacy flags. Intelligence, trial transport and Gmail/SMTP send readiness are also blocked. Ordinary record-only endpoints and nonpaid previews can remain available. All legacy paid flags must additionally remain false for the new conversation gate to pass. Main retail provider routes are outside this fictional campaign and are unchanged.

The native tenant lock row uses a no-change upsert before FOR UPDATE. MySQL INSERT IGNORE's duplicate shared-lock upgrades deadlocked simultaneous pre-dispatch session claims in the new actual-route test. The upsert acquires the writer lock directly, preserving the existing transaction contract and first-row behavior.

## Exact connection approval packet: required before activation

No provider key/account has been read, copied, configured or called. The following must be concretely completed, independently reviewed and approved before enabling the route:

1. Exact reviewed release/build; managed ClientSilo client/silo IDs and current ready binding/schema receipt, private runtime selector and mount. Independently verify sanitized metadata; do not print `.env` or credentials. Proposed known campus scope: `/enterprise-campus`, tenant `1`, Operations `c9634000-0000-4000-8000-000000000006`, verified John user `1`. Actual client/silo IDs and synthetic anchor status remain to be verified; no legacy identity adapter or grants are added.
2. Exact OpenAI account/project (`proj_…`) and optional organization, key ownership/source and approval to use it for this synthetic campus trial. A dedicated scoped key is preferred. An existing/inherited key requires fresh explicit source/account approval; never fall back to retail or ordinary Enterprise keys. Secret entry uses the approved private operator path, never chat. The approval digest binds a one-way key fingerprint, never raw key text.
3. Exact dated model snapshot with official evidence of supported structured output, context limit and token control. Exact default service tier/region/account rates, including worst cache-write and any other fees, conservative integer microUSD ceilings, output bound, overhead, evidence URLs/time and fixed RFC3339 absolute approval expiry. Relative dates, omitted timezone and normalized-invalid calendar dates are rejected. Do not populate guessed prices, unversioned aliases or unsupported models.
4. Verified aggregate prior spend across every earlier demo/trial/acceptance service/account; original evidence hash and exact existing campus ledger UUID and baseline. Its creation requires its own explicit approved operator setup; ClientSilo readiness is not ledger initialization approval. Independently verify every other campus/owner billable route is server-off and has no unresolved in-flight exposure. The campus code cannot attest another private database's state. No cross-schema grants or new infrastructure are authorized by this packet.
5. Final nonsecret `Connection::approvalFields` canonical SHA256 and approval ID, exact user allowlist and expiry; then independently verify the complete config against the approved packet. A changed scope/account/key/model/rate/baseline requires new approval. Changing a ledger's baseline fails closed rather than resetting the cap.

The approved activation is only bounded read-only text conversation. No OAuth, mailbox connection, SMS/email send, payment, voice, saved assistant, persistent memory or business-record write is included. Email tour examples remain previews. Keep activation off until the independent code/CI and exact connection review pass.

## Official documentation used

OpenAI's [structured output guide](https://developers.openai.com/api/docs/guides/structured-outputs) documents the Responses JSON schema shape; application-side validation remains necessary. The [token-counting guide](https://developers.openai.com/api/docs/guides/token-counting) describes token controls; this implementation conservatively reserves the documented full model context. The [spending-controller cookbook](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api) supports reserve-before-I/O, inclusive ceilings and holding uncertainty; this server uses a shared durable MySQL ledger rather than its local-process example. The [conversation-state guide](https://developers.openai.com/api/docs/guides/conversation-state) documents manual history and `store:false`; that flag is not a zero-data-retention guarantee. Actual model/account/rates/data retention still need specific approval and verification.


## Text UI milestone (separate from connection activation)

`ENTERPRISE_CONVERSATION_UI_ENABLED=false` is a separate rollout gate. When enabled, the existing Ask pane shows current workspace/department context and a setup-unavailable state until the exact reviewed connection and existing ledger are ready. It does not activate a provider. The deterministic record checker stays separately labeled. Voice/audio, streaming, tools, sends and work-record changes are unavailable in this text milestone.

Send is explicit. The server owns the short encrypted conversation; the browser stores only opaque session/request receipt IDs in per-runtime/workspace/user/department session storage, never question/history text. Navigation and permission changes clear displayed content and fence late replies. Stop waiting does not abort/refund a potentially completed provider call. Check this conversation performs only read-only availability/recovery GETs; it never replays a POST. New successful turns get a fresh request UUID in the same session, while interrupted turns retain their exact receipt.

Recovery rechecks the current actor, approved connection, unexpired owned session and current source stamp. Changed sources/access require clearing rather than treating history as current facts. Clear needs a specific confirmation and preserves charges/reservations/audit. If a receipt cannot resolve under current access, an explicit local-only forget action removes browser IDs, states that server content/cost exposure remain, and requires a fresh availability check before a new conversation. It does not retry the old question.

Generated answers identify current linked sources and expose deterministic calculation inputs. Estimates are never called approved budgets, missing figures stay missing, and sample records remain labeled. Local browser evidence uses fake HTTP, a fictional model/key and an explicitly seeded private SQLite fixture only; it does not establish live OpenAI or voice acceptance. The fixture converts its in-memory fictional provisioning setup to a disposable persisted SQLite binding solely for the separate browser server, without changing runtime isolation controls.

Checks: `php vendor/bin/phpunit -c phpunit.enterprise.xml tests/Feature/Enterprise/EnterpriseConversationUiTest.php`; `node --test tests/e2e/enterprise-conversation.test.mjs tests/e2e/enterprise-workspace-tour.test.mjs`; after `npm run build:enterprise` and Playwright Chromium/WebKit installation, `ENTERPRISE_TEST_PHP=php node tests/browser/enterprise-conversation.smoke.mjs`. This browser script starts only loopback TLS/PHP servers and deletes its temporary fictional state. CI runs it after browser installation.
