## Scope and authority

The public /platform/demos/lees-mcrae sample retains its existing browser-only fictional session. Its perspectives are demonstration choices, not authenticated identities. The separate private proposal renderer, shared review workspace and native campus silos keep their own permissions and publication admission. No public request client calls those services.

Requests use the current permitted fictional projection. A requester may see their own request without being allowed to open its linked task. REQ-STAGE-07 remains the deliberate example: the Staff perspective sees the request, cannot open restricted task r2, and has no linked operations job. Do not create a substitute job or grant task access to remove that denial. Restricted linked work and absent linked work have different labels.

## Local edits and recovery

Requesters can submit new requests but cannot edit submitted request fields. Only the Admin fictional perspective may edit request title/details, priority, building or assignment, with actual changed-field audit history. This grants no real campus privilege. Priority and building controls start from actual saved values. Intake priorities are Normal, High and Urgent. An existing linked task's Low value is preserved when unchanged. Buildings use the fixed public sample location choices, not arbitrary coordinates, native building IDs or text matches.

Each new local request action uses its opening request version and one retained action key. Current simulated access and explicit links are checked again before the staged mutation is committed. Exact replay returns the original result without duplicate assignments, comments or file references. A conflicting current version refuses; it does not automatically replace an uncertain action key. This is a local simulator contract, not proof of database concurrency or server authorization.

Only successful new owner changes create assignment history. Existing rows without recorded events say Not recorded. Current ownership, task status and receipt existence do not establish a historical assignment. Linked-record synchronization uses explicit saved IDs only and retains unrelated records and policies.

## Comments, files and layout

The request discussion is a separate local thread. Seeing or commenting on a request does not disclose or post into a restricted task thread. Plain comment text is escaped and bounded. Drafts and pending identities are scoped to the current fictional persona and request.

JPEG, PNG and PDF selection uses real browser File objects and bounded type/signature/filename/size checks. The local UI limit is 5 MiB per file and 20 references per request. These checks are not malware scanning. Bytes stay in memory in the current tab; only explicitly identified metadata can survive in the existing session. Files are not uploaded, clean-ready or shared. Reload may require reselecting local bytes. PDFs are not rendered inline, and no private download or scanner URL is borrowed.

Center and Side change the placement of the same dialog/form nodes. Text, selected files, focus and scroll should be retained through placement changes. Mobile request cards and desktop rows render the same permitted filtered requests and actions. Denied or stale replies cannot restore an old persona's content.
