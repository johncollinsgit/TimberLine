# Shared fictional workspace source map reference

This packet is source-only. It does not initialize/migrate a workspace, publish
or replace a proposal, grant campus access, enable a provider or recover browser
edits. Root owns integration, the read-only shared Buildings panel, manifest/CSP
registration, final CI and any separately approved publication transition.

An optional building `map_reference` records exact pinned official catalog ID,
catalog hash, canonical map-number string, PDF URL and legend page2. The drawn
plan is page1; its separately pinned document/points describe printed label
centers, not GPS, real staff positions, ownership or surveyed building bounds.
Unknown keys, null/invalid present references, wrong source/page/hash/number and
changed local asset bytes fail closed. Missing references remain absent.

`ReviewerWorkspaceMapReference` validates private stored graph metadata without
SQL, HTTP or a caller-selected catalog. The source JSON files must ship at their
reviewed fingerprints. The compiled `shared-workspace-map.js` applies the same
closed reference contract before emitting the existing map DTO's map number and
source URL. Root loads this helper before the shared transport and registers its
exact source/CSP/manifest. A present reference without the helper refuses. The
original strict work-view marker resolver still requires exact saved building
identity and current version; text labels, supplied coordinates, stale/foreign
IDs and unlinked tasks cannot manufacture a marker.

The new entry point `node scripts/proposals/reviewer-workspace-map-seed.mjs`
exports a fresh map-enabled fictional seed/evidence; optional `--graph` emits
only its graph. It accepts no browser/session input. It reuses the exact pinned
fixture and a narrow fresh metadata hook in the old exporter. Conflicting saved
map metadata refuses the export. The original default seed output is unchanged.

The new graph requires a separately reviewed seed hash and immutable edition
binding. Do not alter the current publication/descriptor, reinitialize an edited
workspace or silently move comments, grants, pending edits, receipts or budgets.
Older graph-schema1 readers reject the new field, so new map graphs ship only
with the source-bound new reader. New readers continue accepting original graphs
without modifying bytes/digests. AI snapshot schema2 is unchanged; graph/pin
digests change without claiming new native facts or adding map coordinates to AI.

Small separate hooks are supplied for closed PHP graph validation, shared UI
reference decoding/map DTO mapping and the narrow fresh seed metadata function.
The existing server projector already preserves permitted building fields under
its current area/persona filter; no new authority or resource endpoint is added.
Root's future read-only Buildings page can filter the same current projection's
tickets by exact building UUID. Full resources, reservations, collaboration,
uploads and workflows remain outside this packet.
