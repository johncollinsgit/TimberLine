# Reviewed proposal comparison tab

The optional Compare options snapshot leads the proposal sections only when the
saved payload explicitly includes a valid trusted comparison. It is assembled
server-side from the boolean owner choice after CommercialSnapshot::preserve;
clients cannot submit arbitrary comparison content, prices or provenance. The
reviewed source reference, source-copy hash and protected commercial hash must
match the compatible saved terms. Changed or malformed terms fail closed.

The one-workspace and three-workspace figures retain their existing USD prices,
staged activation, usage exclusions and nonbinding status. The bundle arithmetic
compares three separate packages only when all three workspaces are active. This
presentation does not select a package, change the Financial calculator or agree
to payment, overage, access or service activation. Current copy, personal letter
and original commercial fields remain unchanged.

Existing editions without the snapshot retain their original sections/defaults.
An explicit section query or existing error return continues to choose its
permitted section; a comparison-bearing edition defaults to Compare options.
The Activity allowlist adds the section only for a currently valid comparison on
that Version. Event kinds, authorization, bounds and old section constants remain.
Native PDF rendering is outside this source change; the separate rewritten PDF
for wording review is not a published replacement.

CampusReviewManifest includes the comparison class/data/view and their actual
CommercialSnapshot/CommercialSections dependencies. Keep its fixed source count
limit at256 and verify the complete final build; never omit a dependency to fit.

This is source support. A new immutable edition is a separate actual-owner
publication with its own password, audience, expiry and source binding. Do not
inject the tab into or overwrite old immutable payloads, replace an existing
private link, migrate comments or silently initialize a new workspace. When a NEW
fictional workspace is intended, use the explicit reviewed_new_fictional_baseline
basis and honest reviewed-source provenance. It is not recovery of unknown edits;
the preparation/initialization runbooks retain all owner/data/seed/receipt gates.

Verification includes the focused comparison/activity/private-access cases,
old-edition ciphertext preservation, tamper/price refusal and responsive mounted
owner-response layouts in both engines. Normal exact-head CI, independent whole
composition review, protected deployment, hosted owner/recipient acceptance and
any real-provider acceptance are separate states. This change enables no provider,
scanner, SMS/email sending, payment, ledger, credential or real-campus grant.
