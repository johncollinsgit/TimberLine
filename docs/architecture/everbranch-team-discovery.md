## Existing Asana integration

There is real application-side Asana code. It is separate from Codex's development connector:

- `app/Services/Automation/AsanaWorkflowConnectionService.php` implements OAuth authorization, S256 PKCE, 15-minute one-use cached state bound to user/tenant/workflow, callback actor validation, encrypted client snapshot/refresh token, project discovery/cache, and local/provider disconnect.
- `config/services.php:128` declares Asana. Default requested scopes at `:137` are `projects:read,tasks:read,workspaces:read`. The default callback is `/marketing/providers-integrations/workflow-automations/asana/callback`, assembled using the canonical landlord host near `:38`.
- `app/Models/IntegrationConnection.php` encrypts/hides access token, refresh token and OAuth client credentials; stores scopes, expiry, status, connection owner, sync time and last-error fields.
- `app/Services/Automation/V2/Providers/TenantIntegrationConnectionResolver.php` resolves only the selected tenant/provider/connected row. `ProviderAccessTokenService.php` refreshes expired/missing Asana access tokens and preserves the OAuth client that issued the refresh token.
- `app/Services/Automation/V2/Operations/AsanaTaskTriggerOperation.php` polls selected project tasks with pagination, bounded scans, overlapping timestamp/ID watermarks and source fingerprints. Its fields include plain `notes`, dates, tags and custom fields; it is not a full source export. It lacks the requested archive of rich notes, nested relationships, stories/activity, attachments, dependencies and other workspace objects.
- `app/Providers/AppServiceProvider.php` registers QuickBooks and Instagram in the generic `ConnectionManager`; Asana is presently wired through workflow services rather than a registered general connector.

**Health status:** source supports health metadata, but no live token/grant/status was inspected. `AsanaWorkflowConnectionService::status()` may make project API calls and refresh/cache state, so it was not invoked for this read-only source audit. `oauth_connected`/`token_ready` are credential-presence heuristics, not proof of current authorization or complete scope coverage. `granted_scopes` may fall back to requested scopes if the token response omits them. Before a migration, verify the exact customer's connection and chosen workspace with a bounded read probe and record observed permissions; do not print tokens.

The current scopes cannot be treated as a promise of comments/files/team/user coverage. The migration owner must compare required endpoints/scopes against current official Asana documentation, obtain any required owner approval for expansion, and report API/plan-inaccessible content separately. OAuth developer-app distribution, approved redirect registration, actual account plan/deadline and real workspace inventory are not verified by this code audit.

## Concrete isolation and reuse risks

These are confirmed source behaviors, not a claim that an exploit was reproduced in production.

1. **Fail-open helper/global scope.** `HasTenantScope::forTenantId(null)` returns the unfiltered builder. `TenantScope::apply()` is inert when `features.enforced_tenant_scope` is false (the source default) or context is null. Most field/team models inspected use only `HasTenantScope`, not `BelongsToTenant`. `EnforcedTenantScopeTest.php` intentionally preserves the no-context all-tenant behavior. Team services must require a positive resolved tenant and explicit predicates; changing the global legacy contract is a separate coordinator-controlled change.
2. **Web active-membership gap.** `AuthenticatedTenantContextResolver::resolveForRequest()` loads all memberships without `wherePivot('membership_active', true)`. Mobile explicitly filters it. Team access must reject inactive user/membership before object access even if web middleware resolved that tenant. `EnsureTenantAccess` also passes through when the tenant table is empty; new Team routes must fail closed on unresolved tenant.
3. **Global roles may override tenant roles.** `EnsureUserRole::userHasRequiredRole()` accepts `users.role` first and treats blank roles as legacy admin before reading tenant membership. `TenantFinancialAccess::allows()` accepts `platform_admin` and reads membership without active filtering. Team authorization must use the active tenant role plus object grants; historical/global admin flags cannot make a guest a private-project administrator. Landlord access must remain an explicit audited lane.
4. **Callback membership/role gap.** Existing Asana callback checks global `admin/manager/marketing_manager` and membership existence, not active membership or canonical tenant owner/admin authority. Reuse its OAuth mechanics with an import-specific permission and active membership recheck at start/callback/run/resume. State must also bind the requested surface and selected connection; revocation must stop queued reads.
5. **Global provider-token fallback.** `TenantWorkflowAutomationSettingsService::effectiveCredentials()` falls back from tenant PAT/refresh token to global Asana PAT/refresh/access tokens. Shared application client ID/secret is legitimate; another workspace's user grant is not. Team must resolve only a grant stored for that tenant/connection, and reject absent grants. Do not route self-service imports through the legacy effective-credentials fallback.
6. **Tenant is insufficient for private project/guest privacy.** `FieldServiceAccessService` gives current jobs to active members; `TeamCommunicationService::assertAccess()` allows the company channel without project grants. Reusing those semantics for imported private content would broaden access. Also, `FieldServiceAccessService::canUpdateProgress()` returns true for managers before checking the job's tenant, so it assumes callers already scoped the job; do not use it as a standalone Team object guard. A task in several projects needs an explicit validated visibility rule, and comments/files/history/knowledge must inherit the exact effective policy without leaking the private membership/title elsewhere.
7. **Import side effects.** `TeamCommunicationService::post()` dispatches push after new creation. Invitations may deliver SMS. Field task/job observers are registered in `AppServiceProvider`. Imports need a durable import mode that bypasses native notifications/workflow triggers without pretending imported events happened now. Tests must assert zero mail/SMS/push/external writes.
8. **Storage and search need object guards.** Private paths alone do not authorize access. Existing assets/messages are job/channel coupled; new imported files require Team-owned tenant/object checks, checksums, private reads, expiration and export permissions. Retrieval and search require ACL filters before material reaches summaries/embeddings and rechecks when returning links/snippets. Cache keys need tenant, viewer/permission revision and import/source version.
9. **Bud is not general Team AI.** `config/bud.php` defaults AI and voice false; `BudConversationService` is deterministic. `BudWorkspaceContextService::forTenant()` counts all tenant customers/actions without a viewer parameter, so it is not a private-project retrieval contract. `TenantAiUsageService` reserves/settles only `field_voice_transcription`. General summaries/drafting/extraction/semantic search need new measured usage types, concurrency-safe reservations, model configuration, ACL retrieval and owner-approved production budgets/data handling. Existing approval/budget rails are reusable, not proof those capabilities exist.

## Proposed Team boundary

Use one canonical catalog module and the existing tenant/user/billing/session rails. Team owns projects, sections, tasks, task-project memberships, nested parent/dependency links, project grants, guests, source contributors, comments/history, source-note versions, files and reviewable extracted facts. Keep all new domain rows and pivots explicitly tenant-owned; reject cross-tenant related IDs in transactions. Preserve Asana IDs as strings with unique identity `(tenant, provider connection/source workspace, object type, external ID)`, not integer coercion or a global Asana-ID-only key.

Historical contributors are attribution records; verified-email identity mapping is administrator reviewed and never grants membership by itself. Original rich/plain notes, raw evidence and hashes remain access-controlled, immutable/versioned originals. Imported timestamps and authorship are metadata alongside native import timestamps. The source manifest/export is tenant-bound and access at least as restrictive as each source object; do not hand guests an organization-wide export.

Background jobs carry tenant/connection/import-run IDs, re-resolve authorization and selected workspace on every checkpoint, and never call broad global queries. Imported grants precede content visibility. Cancellations/disconnects block subsequent API reads while preserving exported evidence. Source omissions are unknown/inaccessible unless a verified delta/deletion event establishes deletion; never infer deletion from a missing pagination page or revoke attribution because a user disappeared.

AI remains off until production decisions are made. Proposed AI accepts allowed source passages as untrusted data, returns linked suggestions, records model/usage/source versions, and requires explicit human application for writes. It cannot send invitations/messages, change assignments or rewrite imported history. Deterministic searchable originals remain useful without AI.
