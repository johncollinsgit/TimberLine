## Shared product architecture

One tenant-owned project/task graph is the canonical foundation for desktop and the existing React/TypeScript Capacitor iOS/Android app. No second task system, app, authentication store or billing engine is introduced. `WorkGraph` is the command/query layer; `TeamWorkRepository` persists it transactionally in Laravel. `TeamWorkAccess`, model policies, `routes/team.php`, `TeamWorkController` and the existing app sidebar serve the real responsive screen. A default-off native bearer API adapter is implemented; native renderer integration remains pending. See `everbranch-team-integration-contract.md`. Team is default-disabled with an exact tenant-ID allowlist and canonical `team_work` entitlement; no real tenant was enabled.

Persistence now uses additive project, task, project member, project-task membership, tenant command-lock, immutable native version, activity, receipt and per-recipient Inbox tables. Upload/chunk metadata uses two additional Team tables, with bytes on a non-served private disk. Section/typed-field definitions and native comments currently live in versioned entity payloads. Task identity is independent of project membership; section/order are on the membership. Each accepted mutation commits entity, native revision, activity, receipt and eligible internal Inbox records together. Initial repository operations load a tenant graph and serialize commands per tenant; large-scale indexing/performance are not accepted yet. A Field Service extension can relate canonical work to a job without duplicating history, but that adapter is not yet wired into existing Field routes. Existing `FieldServiceTask` records and permissions remain unchanged. No legacy task or source migration was performed.

Server controllers/workers must derive actor context from active verified membership, canonical module access and current object permissions. Never pass client-provided `active`, `role`, `entitled`, `active_user_ids`, job IDs or trusted import bindings directly to these contracts. Owners/admins have no implicit private-project bypass. Tenant role is separate from project editor/viewer grant. Guests see explicit shares only. Task assignment does not grant access. Shared task content is visible through an authorized membership; adding another membership requires sharing review and edit access to every existing membership. New private projects default to private.

Unhomed subtasks inherit their parent's ACL; homed subtasks require parent access plus their own access. Nesting is capped at five parent edges. Parent completion never cascades. Task projections remove unauthorized project memberships and Field job references. Source originals are separate immutable versions, not overwritten descriptions. Version checks reject stale descriptions; activity currently records command/actor/time/field names, avoiding old private text in public projections.
