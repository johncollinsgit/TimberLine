# Everbranch Team: first migrated project UI and test plan

Date: 2026-10-11. Public technical implementation sequence after Phase 1 preservation and scope review. The restricted coordinator report contains actual source counts, account/plan details and private preview coverage. This document does not create Team schema, code or routes, and no application deployment has occurred.

## Slice and evidence boundary

Use a read-only preserved snapshot of an explicitly selected workspace and a candidate representative private project. Exact customer names, source IDs, source statistics and original records belong only in the restricted private evidence. Confirm the preserved manifest's project/task/comment/attachment coverage before declaring it the slice. Preservation of private membership is a prerequisite, not optional polish. Additional workspaces require an explicit source-scope decision.

The candidate is valuable because older project notes coexist with much newer follow-up task evidence. Both must stay readable and searchable. An extraction review should surface the conflict, preserve the original passages independently, and let an authorized administrator decide whether either fact belongs in a current field. Neither import date nor newest timestamp makes one passage authoritative by itself. Do not commit raw contacts/notes to the source repository; real preserved fixtures belong in access-controlled staging storage. This candidate has not been imported into the application, and complete history has not been verified.

Classification: purchasable Team Branch. Tenant variation: project memberships, source connections/selections, labels, enabled views, extracted field mappings and notification preferences. Billing: reuse existing Stripe/catalog/entitlement services; pricing undecided and no live charges authorized. Shared contracts: tenancy/membership, `TenantModuleAccessResolver`, `UnifiedAppNavigationService`, existing private storage/audit conventions, supported Asana OAuth and billing services. The slice must work in a fictional second tenant without changing runtime code.

## Proposed UI seam and sequence

Path names below are proposed, not existing application files. The coordinator owns final schema and route naming. Prefer a canonical `/team` route group and a dedicated `resources/js/team/` renderer if accepted; extend TypeScript checks to cover it. Existing job routes and client implementation project routes retain their domain meaning.

1. **Entitled shell and safe project navigation.** A Team destination enters a workspace-specific sidebar with My Tasks and accessible projects. Group by source team only when evidence confirms that relationship. Show archived projects under an explicit archive filter. Never include a private project title, count, avatar or snippet in a response unless the viewer may see it. Initial migration UI is owner/admin only and offers connection health, permission coverage, source scope and manifest status.
2. **Preserved project overview.** Show project name, archive state and an Original project notes panel with source/import timestamps and a source link. Original rich text is sanitized for rendering while the raw source is retained privately. Long notes can expand/search without being hidden in a tooltip. Show a preservation coverage summary and unresolved items to administrators; ordinary members see only authorized operational content.
3. **List and detail.** Render sections, tasks, assignee, due date and completion inline. Opening a task uses a task detail panel with source identity, full description, accessible comments and attachments. The same task can appear in multiple projects, with one detail identity and project-specific positions. Add subtasks only when the parent snapshot/edge has been preserved. Include readable unknown/former contributor attribution without granting access.
4. **Controlled edits and My Tasks.** Allow native draft/edit/complete/assign operations through object-authorized routes, keeping original snapshots immutable and import history separate. My Tasks filters by verified current identity, with overdue/upcoming/no-date buckets; historical/imported author names never grant ownership. Drag ordering has explicit keyboard Move up/down/move-to-section actions.
5. **Date and note conflict review.** A review drawer places source project and task passages side-by-side, each with its own timestamp/version/source reference. Extracted date/contact/amount suggestions are pending until confirmed. A current typed fact links to the accepted passage; conflicting or absent evidence has a distinct state. Undo restores the preceding accepted mapping without rewriting source snapshots.
6. **Calendar and board acceptance.** Calendar uses actual preserved task start/due fields and separately labels inferred/suggested dates pending review. Date-only values stay date-only in the user's timezone. Board columns follow source sections/status only after that mapping is explicit; do not invent a board for every imported list. Saved views are scoped to tenant/user in the server contract and contain no cached unauthorized project data.
7. **Cutover review.** Present slice reconciliation counts, original text checks, missing attachment failures and source relationship differences beside a short where-things-moved guide. Administrator approval of a slice does not automatically migrate all projects or send invitations. A second delta import must show source changes and preserve local edit conflicts for review.

## Component-level acceptance

| Proposed UI component | Required data and permission seam | Observable result |
| --- | --- | --- |
| `TeamWorkspaceShell` / `ProjectNavigation` | Active tenant entitlement plus allowed project IDs; counts derived from the same ACL query. | Switching tenants empties previous results before loading; inaccessible projects never flash. |
| `ProjectList` / `TaskRow` | Project/section membership, membership order, task identity, assignment and date-only/timed values. | Inline edits reconcile server errors; moving one membership does not move every occurrence of the task. |
| `TaskDetailPanel` | Task visibility through an accessible membership or explicit personal rule; comments/assets individually guarded. | Deep links resolve authorization again; Escape restores focus to the originating row; mobile uses full-width detail. |
| `OriginalNotes` / `NoteReviewDrawer` | Original record version, sanitized readable representation, source passage offsets/references and permission-filtered suggestions. | Historical project notes and newer task evidence coexist; ambiguous fields remain pending; undo is auditable. |
| `TeamCalendar` / `TeamBoard` | ACL-filtered tasks and explicit membership/date mapping. | Unscheduled/no-date items remain accessible; board moves are persistent and keyboard accessible. |
| `MigrationPreview` / `Reconciliation` | Owner/admin access, immutable manifest, object-type counts and explicit missing/unsupported/failure categories. | Resuming reflects actual checkpoint progress; cancellation leaves recoverable source bytes and no false success badge. |

Real source snapshots must not be committed, sent to unauthenticated browsers, or used in public demo pages. Each fixture manifest records source identity, workspace/project scope, captured timestamp, hashes, coverage and expected relationships.

## Test execution gates

Gate 1: preservation manifest/identity/membership coverage complete enough for the chosen project. Gate 2: schema and domain contracts approved by coordinator, migration linter and real MySQL durable partial-state recovery tests pass. Gate 3: focused Team Pest tests pass in SQLite plus necessary MySQL integration tests; fixtures cover object guards on direct API and queued paths. Gate 4: Team TS included in typecheck, Vite build passes and authenticated browser tests pass at desktop and phone widths. Gate 5: representative real-source slice reconciled and reviewed before any wider migration or cutover.

The existing `npm run test:visual` is a public-site suite and `test:highlevel-fleet` is a specialized Fleet browser suite. Neither verifies these proposed flows. Create authenticated Team browser fixtures in a disposable local/staging environment and test actual sidebar/list/inline edit/detail/keyboard/board/calendar/review/resume paths. Use screenshots for phone/desktop review, but do not place private source notes or credentials in unrestricted artifacts. Live Asana remains available throughout validation.

Current evidence: plan only. No Team UI, migrations, import records or browser verification created here.
